# Инженерные кейсы

[Профиль](../README.ru.md) · [English](README.md) · [Путеводитель по открытому коду](../PROJECTS.md)

Я разрабатываю Python API и бизнес-процессы с явными правилами доступа, сохранения изменений и восстановления после ошибок. Четыре кейса ниже показывают конкретные решения. Подробные разборы написаны на английском.

## Sfera

**Согласованное сохранение совместных изменений.** Устаревшая вкладка не должна перезаписывать новые данные. Проверка версии, блокировки БД и транзакционные операции защищают изменения таблиц; объектные права и история документов помогают контролировать и восстанавливать работу.

[Читать разбор](sfera.md) · Django/DRF, FastAPI, PostgreSQL, Celery, React/TypeScript

## PDF Label Service

**Резервирование кодов до выпуска этикеток.** После прерванного экспорта PDF уже может существовать. Транзакционный журнал и отдельное состояние ручной проверки не позволяют автоматически вернуть сомнительные коды в доступный пул.

[Читать разбор](pdf-label-service.md) · FastAPI, SQLite, pypdf

## AI English Companion

**Учёт использования AI и платного доступа.** Повторное подтверждение платежа не должно повторно продлевать подписку. Сохранённые идентификаторы событий, атомарные изменения доступа и учёт запросов связывают Telegram-интерфейс с правилами оплаты.

[Читать разбор](ai-english-companion.md) · Python, aiogram, SQLite, Pytest

## Ping

**От неоднозначного сообщения к сохранённому напоминанию.** Пользователь подтверждает текст и время до сохранения. PostgreSQL хранит расписание между перезапусками; API проверяет владельца личных данных.

[Читать разбор](ping.md) · FastAPI, PostgreSQL, Docker, React/TypeScript
